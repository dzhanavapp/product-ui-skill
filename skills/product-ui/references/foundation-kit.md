# Фундамент: токены и базовые компоненты

Здесь — требования к качеству и проверенные приёмы. Какие компоненты нужны продукту и как они выглядят, решает
дизайн-план (этап 2). Образцы кода — отправная точка, адаптируй под продукт.

## Токены
Все цвета, радиусы и шрифты — переменные в одном месте; компоненты используют только их.
```css
@theme inline {
  --font-heading: '<шрифт заголовков>', '<шрифт текста>', sans-serif;
  --font-sans: '<шрифт текста>', system-ui, sans-serif;
  --color-accent-brand: var(--accent-brand);
  --color-surface: var(--surface);
}
:root {
  --background: <hex>; --foreground: <hex>;
  --surface: <hex>;    --muted-foreground: <hex>;
  --primary: <hex>;    --primary-foreground: <hex>;
  --accent-brand: <hex>; --ring: <hex>;
  --radius: <значение>;
}
@layer base { :focus-visible { outline: 2px solid var(--ring); outline-offset: 2px; } }
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```
Требования: у акцентного цвета есть определённая роль, записанная в DESIGN.md, и он не используется для украшения;
контраст текста достаточен; если тем две, проверены обе.

## Навигация
Устройство навигации определяет дизайн-план. Независимо от решения:
- текущий раздел всегда понятен;
- на каждом типе устройства навигация удобна для основного способа ввода (палец, мышь, клавиатура);
- переход на новую страницу начинается сверху, а «Назад» возвращает на прежнюю позицию прокрутки;
- фиксированные элементы не перекрывают контент и учитывают безопасные зоны экрана (`env(safe-area-inset-*)`);
- отступы контента и элементов «на всю ширину» согласованы между собой.

## Изображения
Место под изображение зарезервировано заранее (соотношение сторон задано у контейнера), поэтому макет не сдвигается.
Изображение появляется плавно, при ошибке показывается аккуратная заглушка. `alt=""`, если рядом есть видимая подпись.
```tsx
export function Img ({ src, alt = '', className, imgClassName, fallback }: Props) {
  const [state, setState] = useState<'loading' | 'ok' | 'error'>(src ? 'loading' : 'error')
  useEffect(() => setState(src ? 'loading' : 'error'), [src])
  return (
    <div className={cn('relative overflow-hidden bg-muted', className)}>
      {src && state !== 'error' && (
        <img src={src} alt={alt} loading="lazy" decoding="async"
          onLoad={() => setState('ok')} onError={() => setState('error')}
          className={cn('size-full object-cover transition-opacity duration-500', state === 'ok' ? 'opacity-100' : 'opacity-0', imgClassName)} />
      )}
      {state === 'error' && (fallback !== undefined ? fallback : <Placeholder />)}
    </div>
  )
}
```

## Состояния
- **Загрузка** повторяет форму будущего контента: скелетон тех же размеров. Крутящийся индикатор — только для
  коротких действий внутри кнопки или когда форма контента неизвестна.
- **Пусто** — иконка или иллюстрация, заголовок, одна строка пояснения, одна кнопка-действие.
- **Ошибка** — что случилось и что делать, кнопка «Повторить». Сетевые сбои браузера переводятся в понятный текст:
```ts
export function humanError (error: unknown) {
  const e = error as Error
  if (!e?.message || e.name === 'TypeError' || /fetch|network|load failed/i.test(e.message)) return 'Нет связи с сервером. Проверьте подключение и попробуйте ещё раз.'
  return e.message.replace(/\.$/, '') + '.'
}
```

## Списки и подгрузка
- Бесконечная подгрузка — через IntersectionObserver с запасом около 300px (больший запас подтягивает лишние
  страницы на высоких экранах). Она активна, только когда есть следующая страница и она ещё не грузится; пока идёт
  подгрузка, показываются скелетоны.
- Горизонтальные ленты, если они есть в плане:
  - нативная прокрутка с привязкой (`scroll-snap`);
  - управление для мыши отдельно от касаний;
  - вертикальное колесо не перехватывается;
  - у контейнера нет вертикальной прокрутки (`overflow-y-hidden`), крупные элементы ограничены рамкой;
  - на телефоне виден край следующего элемента.
- Длинные списки с фильтрами хранят состояние в URL, поэтому «Назад» и обновление страницы его восстанавливают.

## Сложные интерактивные экраны
Сложную логику (редакторы, проигрыватели, конструкторы, мастера) держи в отдельном модуле или классе, а интерфейс
пусть только отображает его состояние. Обязательно:
- работа с клавиатуры;
- жесты там, где основной ввод — касание;
- корректная работа в полноэкранном режиме (всплывающие меню видны);
- отмена долгих операций.

## Разные браузеры
Отдельно проверяй то, что зависит от браузера: форматы медиа и способ их отдачи, автозапуск звука, единицы высоты
экрана (`svh`, `dvh`), безопасные зоны, полноэкранный режим. Safari и iOS строже остальных: если продуктом будут
пользоваться с устройств Apple, проверяй их всегда.
