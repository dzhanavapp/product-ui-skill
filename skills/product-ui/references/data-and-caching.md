# Данные, кэш, оптимистичные действия, ожидание

Цель: повторные визиты открываются мгновенно, лимиты внешних сервисов не расходуются впустую, действия
пользователя отражаются сразу.

## Уровни кэша
1. **Сервер, на диске (stale-while-revalidate)** — для внешних API, особенно платных или с лимитами:
```js
const store = loadJson(FILE)          // { key: { t, v } }
const inflight = new Map()
function run (key, fn) {
  if (!inflight.has(key)) inflight.set(key, Promise.resolve().then(fn)
    .then(v => { store[key] = { t: Date.now(), v }; persistSoon(); return v })
    .finally(() => inflight.delete(key)))
  return inflight.get(key)
}
export async function cached (key, ttl, fn) {
  const e = store[key]
  if (e && Date.now() - e.t < ttl) return e.v           // свежее
  if (e) { run(key, fn).catch(() => {}); return e.v }    // устарело: отдаём сразу, обновляем в фоне
  return run(key, fn)                                     // нет: ждём; одновременные запросы склеиваются
}
```
   - Время жизни выбирай по смыслу данных: что меняется редко — часы и дни, поиск — около суток, живые данные — минуты.
   - Ограничь размер кэша. При ошибке или исчерпании лимита отдавай последнюю сохранённую версию.
   - Ответ «не найдено» тоже кэшируй. Один подробный ответ переиспользуй для нескольких экранов вместо разных запросов.
   - Для API с ограничением запросов в секунду нужна очередь: не больше N одновременно, пауза между стартами,
     повтор при ответе 429.
2. **Браузер — кэш запросов с сохранением в localStorage**, только для тяжёлых и редко меняющихся данных:
```ts
const persister = createSyncStoragePersister({ storage: localStorage, key: '<app>:query-cache', throttleTime: 30_000, retry: removeOldestQuery })
const PERSIST = new Set([/* ключи тяжёлых и стабильных запросов */])
<PersistQueryClientProvider client={qc} persistOptions={{ persister, maxAge: 3 * 24 * 3600_000, buster: 'v1',
  dehydrateOptions: { shouldDehydrateQuery: q => q.state.status === 'success' && PERSIST.has(String(q.queryKey[0])) } }}>
```
   Не сохраняй поиск, бесконечные списки и то, что часто опрашивается: иначе весь кэш постоянно пересериализуется.
   Ставь `refetchOnWindowFocus: false` там, где данные не устаревают за минуты. Если изменился формат данных,
   поменяй `buster`.
3. **HTTP-заголовки**: `Cache-Control` для ответов API, `immutable` для статики и картинок с хешем в имени.

## Хуки данных
- `staleTime` задавай по типу данных, а не один на всё приложение.
- При смене фильтров и страниц показывай прошлые данные, пока грузятся новые (`placeholderData`), но не между разными
  разделами: иначе под новым заголовком мелькает чужой контент. Затемняй такие данные по `isPlaceholderData`.
- Поиск: задержка не меньше 600 мс, минимум 3 символа, если API лимитирован, запрос в URL, недавние запросы — локально.
- Предзагрузка по наведению: только мышь, задержка около 700 мс, бюджет на сессию; уже загруженное пропускается,
  а таймер отменяется, когда курсор уходит.
- Состояние фильтров хранится в URL.

## Оптимистичные действия
- Локальные списки (избранное, история, черновики) — модуль-хранилище плюс `useSyncExternalStore`, синхронизация между
  вкладками по событию `storage`. Действие сразу меняет интерфейс, а уведомление с «Отменить» возвращает ровно то,
  что изменилось.
- Серверные действия — `useMutation`:
  - `onMutate`: снимок данных и мгновенное изменение;
  - `onError`: откат и понятное уведомление;
  - `onSettled`: обновление данных.

  Если сущность опрашивается, опрос приостанавливается, пока идёт мутация (`useIsMutating`). Иначе ответ сервера
  перетирает мгновенное изменение.
- Сохранение настроек: подтверждение показывается сразу; при ошибке появляется сообщение, а введённое остаётся в форме.

## Живое ожидание
```ts
export function useElapsed (running: boolean, resetKey?: unknown) {
  const [sec, setSec] = useState(0)
  useEffect(() => { setSec(0); if (!running) return
    const started = Date.now(); const id = setInterval(() => setSec(Math.floor((Date.now() - started) / 1000)), 1000)
    return () => clearInterval(id) }, [running, resetKey])
  return sec
}
// подсказка становится подробнее со временем
export const waitHint = (sec: number, s: { explain: string; almost: string; action: string }) =>
  sec < 6 ? '' : sec < 20 ? s.explain : sec < 45 ? s.almost : s.action
```
- Многошаговый процесс показывается списком шагов: выполненные отмечены, у текущего — индикатор и счётчик секунд,
  подсказка объявляется скринридеру (`aria-live="polite"`).
- Перегрузка сервера (503) — не ошибка, а очередь: понятный текст, автоповтор, отмена, общий предел ожидания.
- Долгие операции отменяемы; уход со страницы отменяет то, что было запущено с неё.

## Ресурсы сервера
Тяжёлые операции идут через ограничитель параллельности и при переполнении дают понятный ответ. Большие временные
данные хранятся на диске с вытеснением старого и пределом, зависящим от свободного места, а не в оперативной памяти.
