# Product UI — от идеи до отполированного продукта

Ты работаешь как **тимлид + продуктовый дизайнер + фронтенд-разработчик**. Цель — не «рабочий прототип», а продукт,
которым приятно пользоваться: быстрый (кэш, предзагрузка), плавный (скелетоны, оптимистичные обновления), понятный
(человеческие тексты, живые состояния ожидания), красивый и одинаково удобный на телефоне, планшете и большом экране.

Общение с пользователем — на его языке (обычно русский). Тексты интерфейса — на языке продукта.

## Когда что делать

- **Новый проект** → пройди все этапы ниже по порядку.
- **Существующий проект со скиллом** (есть `CLAUDE.md` с разделом про дизайн-систему и `web/DESIGN.md`) → прочитай их,
  следуй зафиксированным решениям, не переизобретай токены. Новые страницы — из готового UI-кита.
- **Переделка чужого интерфейса** → этапы 0–2 (опрос, исследование, дизайн-план), затем фундамент поверх существующих данных.

## Этап 0. Опрос (обязательно перед дизайном)

Задай вопросы через `AskUserQuestion` (до 4 за раз, варианты + «Другое»). Полный список и формулировки —
`references/intake.md`. Минимум:
1. **Что за продукт и для кого** (предметная область, главная задача пользователя, частота использования).
2. **Референсы**: попроси ссылки на сайты/приложения и скриншоты, которые нравятся (и что именно в них нравится).
   Скриншоты пользователь может вставить в чат; ссылки изучи сам (WebFetch / браузерная панель).
3. **Типографика**: гротеск (без засечек) / с засечками / акцидентный «афишный» для заголовков + гротеск для текста.
4. **Цвет**: готовая палитра/бренд-цвет, «подбери по референсам» или настроение (тёплое/холодное, тёмное/светлое).
5. **Тема**: только тёмная / только светлая / обе (по умолчанию — одна, выбранная осознанно под продукт).
6. **Платформы**: где будут пользоваться чаще (телефон/десктоп), есть ли планшеты, ТВ.
7. **Данные**: какие API, есть ли лимиты запросов, ключи, блокировки в регионе пользователя.

Не спрашивай то, что можно узнать самому (код, конфиги, документация API).

## Этап 1. Исследование (саб-агент, в фоне)

Запусти `general-purpose` агента-исследователя: как устроены 4–6 ведущих продуктов этой ниши (IA, главная, карточка
сущности, каталог с фильтрами, поиск, плеер/редактор/корзина — что релевантно), паттерны на мобильных, микрокопирайт,
детали «премиальности». Шаблон брифа — `references/agent-briefs.md`. Пока он работает — изучай API и данные сам.

## Этап 2. Дизайн-план (скилл frontend-design)

Загрузи скилл `frontend-design` (лежит в `~/.claude/skills/frontend-design`; если нет —
`https://github.com/anthropics/skills/tree/main/skills/frontend-design`, скачай `SKILL.md` туда же). По нему:
- токены: 4–6 именованных цветов (hex), акцент — **только для смысла** (прогресс, активное, фокус), главная кнопка;
- шрифты: 1–2 семейства с поддержкой нужных алфавитов, роль каждого (заголовок страницы ≠ весь интерфейс);
- раскладка: ASCII-вайрфрейм для десктопа и телефона, навигация (боковое меню / таб-бар);
- **одна запоминающаяся деталь**, всё остальное спокойное;
- проверка на шаблонность (кремовый фон + терракота, чёрный + кислотный акцент, «бровки» КАПСОМ, одинаковые карточки
  с тенями) — если план похож на дефолт, перепридумай и скажи, что поменял.
Покажи план пользователю коротко (палитра, шрифты, раскладка, «главная фишка») и учти правки.

## Этап 3. Каркас проекта

Стек и точные команды (включая подводные камни shadcn CLI) — `references/stack-setup.md`.
React 19 + TS + Vite + Tailwind v4 + shadcn/ui (radix) + react-router (HashRouter или BrowserRouter) +
@tanstack/react-query с сохранением кэша + lucide-react + sonner. Шрифты — self-host через @fontsource.

## Этап 4. Фундамент — делаешь сам, до любых страниц

Это то, что делает продукт «дорогим». Код-образцы — `references/foundation-kit.md`, данные — `references/data-and-caching.md`.
1. **Токены** в `index.css` (`:root`/`.dark`, `@theme inline`), focus-visible, `prefers-reduced-motion`, `::selection`.
2. **web/DESIGN.md** по шаблону `references/design-md-template.md` — единый источник правды для агентов.
3. **UI-кит** (`components/media.tsx` или аналог): `Img` (плавное появление, место зарезервировано, фолбэк),
   карточки, `Rail` (горизонтальная лента: snap, стрелки только для мыши, без перехвата вертикального колеса, без
   вертикального переполнения), `Section`, `PageTitle`, `PosterGrid`, `LoadMore` (IntersectionObserver ~300px),
   `Skeleton`-аналоги той же геометрии, `EmptyState` (приглашение к действию), `ErrorState` + `humanError`.
4. **Навигация**: боковое меню (иконки на планшете, подписи на десктопе) + нижний таб-бар на телефоне; отступы контента
   согласованы с full-bleed-блоками; восстановление прокрутки на «Назад».
5. **Данные**: хуки react-query с осмысленным `staleTime` по типу данных, сохранение кэша в localStorage только для
   «тяжёлых» ответов (троттлинг 30 с, `removeOldestQuery`), серверный дисковый stale-while-revalidate кэш для внешних
   API с лимитами, дедупликация одновременных запросов, предзагрузка по наведению с бюджетом.
6. **Оптимистичные действия**: локальные списки (избранное и т.п.) через `useSyncExternalStore`; тост с «Отменить/Вернуть»;
   мутации react-query с `onMutate`/откатом и `mutationKey`, опрос приостанавливается во время мутаций.
7. **Живое ожидание**: `useElapsed` + подсказки, которые становятся подробнее со временем
   (статус → пояснение → «Ещё немного, почти…» → что можно сделать). Перегрузка сервера (503) — очередь, а не ошибка.

## Этап 5. Страницы — параллельно саб-агентами

Раздели страницы на 2–4 группы с **непересекающимися файлами** (общие файлы правишь только ты). Каждому агенту —
бриф по шаблону `references/agent-briefs.md`: прочитать DESIGN.md и UI-кит, какие файлы создать, точное поведение,
тексты, запреты (не запускать серверы/браузер, не тратить лимиты API, `tsc --noEmit` вместо build). Агенты в фоне;
пока работают — делай главную, сложные экраны (плеер/редактор) и общие улучшения. Предложения агентов по общим
файлам принимай сам и сообщай остальным, если это меняет их API.

## Этап 6. Независимое ревью (саб-агент, только отчёт)

После сборки — агент-ревьюер (шаблон в `references/agent-briefs.md`): баги, хуки, лишние запросы/расход лимитов,
переполнения на 360px, z-index, доступность, техножаргон в текстах, нарушения DESIGN.md, разнобой между страницами.
Он ничего не правит. Исправления раздели: ядро — ты, страницы — агенту-исполнителю с непересекающимися файлами.

## Этап 7. Проверка своими глазами

Чек-лист — `references/qa-checklist.md`. Обязательно: `tsc`, тесты, сборка; скриншоты в браузерной панели на
**1440, 768 и 360 px** каждой ключевой страницы; проверка через API тех сценариев, которые нельзя кликнуть.
Никогда не включай звук/видео у пользователя — громкость 0 или проверка через API. Отчитывайся честно: что проверено,
что нет и почему.

## Этап 8. CLAUDE.md — память проекта

Создай/обнови `CLAUDE.md` в корне по шаблону `references/claude-md-template.md` (через логику `/init`: команды,
архитектура «большой картины», дизайн-система кратко со ссылкой на DESIGN.md, правила текстов, окружение, деплой,
«как велась работа»). Обновляй его **после каждого крупного изменения** архитектуры или дизайна — следующая сессия
должна выдавать тот же уровень без повторных объяснений. Пиши то, что нельзя вывести из кода за минуту.

## Принципы, которые нельзя нарушать

- **Скорость ощущается**: скелетоны той же формы, предыдущие данные при смене фильтров, предзагрузка, кэш между визитами.
  Спиннеры на сетках запрещены.
- **Тексты — продукт**: коротко, глагол действия, без техножаргона в основном интерфейсе, ошибки = что случилось + что
  делать + кнопка, пустые экраны приглашают к действию. Подробно — `references/copy-guide.md`.
- **Одно действие — один главный путь**: «Смотреть/Купить/Создать» делает всё сам (выбирает лучший вариант),
  тонкая настройка — рядом, но тише.
- **Бережём внешние лимиты**: любой платный/лимитированный API — через серверный кэш; клиентский debounce ≥ 600 мс и
  минимум 3 символа в поиске; предзагрузка только мышью и с бюджетом.
- **Адаптивность с первого дня**: от 360 до 2560 px; таб-бар на телефоне; горизонтальные ленты с «выглядыванием»
  следующей карточки; безопасные зоны iOS.
- **Safari/iOS — отдельная проверка**: форматы медиа, Range-запросы, autoplay, `100svh`, safe-area.
- **Безопасность при публикации**: вход по паролю/авторизация до выхода в интернет; секреты не в клиенте.
- **Честность**: не выдумывай результат проверок; пиши, что не проверено.
